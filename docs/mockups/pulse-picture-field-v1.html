One picture field for every posting form

The same field in the poll form and the contribution form, at desktop and phone width. One picture per post, a required description, and errors that never clear what you wrote. Discussion topics (#541) will use the same field.

The field on its own, every state

At the desktop form's column width (520 px of content). The phone frames further down show the same states sized for touch.

In the poll form

The field sits right under the question, so the picture belongs to the question, the way Reddit puts it under the title.

In the contribution form

The field sits right under the description, before the organizer's name.

Every message the field can show

The table lists the exact wording, including variants without a frame. Limits are ADR-0047's, kept by ADR-0049.

How it behaves

Steps

  1. Choose a picture. The file chooser accepts JPEG, PNG and WebP only (on an iPhone this also turns a HEIC photo into a JPEG before it leaves the phone).
  2. Size and file type are checked in the browser first, so a 14 MB file is refused at once, without uploading.
  3. The upload starts straight away. The preview is the local file, shown while it uploads; the description can be typed meanwhile.
  4. Posting attaches the uploaded picture and its description to the post in one step. A post without a picture is fine; a picture without a description is not.

Drafts are never lost

  • A refused file, a failed upload or a busy server changes only this field. The question, choices, title, description and every other field stay exactly as typed.
  • After a network or busy error the chosen picture and its description stay too, with Try again beside Remove.
  • Remove clears the picture and its description; the rest of the draft stays.
  • Replace goes through the uploading state again. "Picture replaced…" is announced only once the new upload succeeds; until then the old description is kept.
  • If Post refuses an expired or otherwise unavailable picture, the picture clears and focus moves to Choose a picture. Its description and the rest of the draft stay.

Keyboard and screen readers

  • The field is a group named "Picture (optional)". "Choose a picture", "Replace" and "Remove" are ordinary buttons in tab order; the hint is tied to them as their description.
  • Upload progress, "Picture uploaded", "Picture removed" and "Picture replaced…" are read from a polite status line. Errors are tied to the button or the description box and marked invalid; pressing Post moves focus to the first one.
  • After Remove, focus goes to "Choose a picture" (drawn with the green focus ring). After Replace, focus goes to the new picture's "Replace" button.
  • The preview's text alternative is "Preview of the picture you chose", not the description, so it is not read twice next to the description box.

Not in this field, on purpose

  • No second picture, gallery, crop tool, filters or caption separate from the description (one picture per item, ADR-0049 E2).
  • No drag and drop or paste in this version; Choose a picture is the one way in.
  • Removing or replacing the picture of an already-posted item is a separate surface (#582 and #701's routes), not this form.
