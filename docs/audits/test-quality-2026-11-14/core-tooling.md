# Core, tooling and guard test-quality audit — cf07079

Snapshot: detached `/workspace/odc-audit-core`, commit `cf07079`. Audit date 2026-11-14. No fixes, commits, pushes, issue creation, checkout/reset/stash, or lasting tracked changes. Verifier source and verifier tests were never opened. References below are relative to this snapshot.

## Assessment

The suites contain substantial useful assertions: hand-derived hashing anchors, committed-byte checks that survive regeneration, independent expectations for canonical integers/Unicode, runtime-role and owner-role storage guards, forced writer-lock contention, real HTTP reads/writes, and persisted-request recovery. They are much stronger than simple round trips. Their green results do not establish design quality or full conformance.

Four actionable test gaps/false-green paths and one historical harness limitation follow. The startup gap and guard invocation failure deserve first attention. There is no evidence supporting a broad test rewrite or mass deletion.

## Findings

### C1 — P2 / SHOULD: guard tests never exercise failed Git discovery, and both PR guards currently pass it

Locations: `.github/scripts/guards.test.sh:71-84`; `.github/scripts/contracts-guard.sh:28-35`; `.github/scripts/diff-size.sh:73-90`.

Every guard fixture invokes a valid `BASE=base HEAD=HEAD`. The harness correctly checks negative diagnostics and setup failures, but never tests failure of the guard's own input-discovery command. Bash does not propagate failures from these process substitutions through `set -e`/`pipefail`. A missing base ref is therefore reported as no changed files, bypassing contract/version/freeze checks and diff limits.

Concrete unmodified-snapshot repro, from the snapshot root:

```sh
BASE=does-not-exist HEAD=HEAD bash .github/scripts/diff-size.sh
BASE=does-not-exist HEAD=HEAD bash .github/scripts/contracts-guard.sh
```

Both exit **0**, after `fatal: bad revision 'does-not-exist...HEAD'`. The first prints `Changed lines ...: 0` / `diff-size OK.`; the second prints `No contracts/ changes; contracts-guard passes.` The regular guard suite still passes all 39 scenarios. This is an actual fail-open condition, not a hypothetical mutation.

Contained fix: capture/check `git diff` before feeding its output to the loops, or explicitly validate refs/merge base and handle command failure. Add missing-base, missing-head, and unavailable-merge-base cases which require a nonzero exit and an input-discovery diagnostic. The same process-substitution pattern in `memory-index.sh:43` merits a no-HEAD/nonrepository regression; this audit did not claim its reproduction as a separate defect.

### C2 — P2 / SHOULD: the production ledger entry point has no executable wiring test

Locations: `services/ledger/tests/server/wiring.test.ts:25-35`, `tests/server/write-harness.ts:37-49`, versus `src/main.ts:21-56`.

The suite named wiring creates `new Batcher(...)`, opens its own Ledger, and calls `buildServers` itself. It manually calls `tick()` in test bodies. No scoped test imports or spawns `src/main`/`dist/src/main.js`, or calls `createBatcher`. Therefore it does not exercise production's recovery-before-listen ordering, validity-dependent startup, scheduled batching, actual configuration/ports, or signal shutdown. Timer and recovery units cover their components, but cannot catch omitted/misordered calls in main.

Mutation probe: replace the body of `createBatcher` (`src/batching/batcher.ts`, final function) with `throw new Error("AUDIT startup factory broken")`, rebuild ledger, then run the regular ledger suite. This makes every production launch fail immediately while preserving the constructor used by tests. The successful rerun result is recorded in the execution section below. An earlier attempt after the environment restart hit a missing DB and is explicitly excluded as mutation evidence.

Contained fix: add a small process/startup seam test using a migrated throwaway DB and the existing HTTP signer double. Persist a pending sign request first; hold replay at a barrier and prove internal requests cannot be accepted before it, then release and observe eventual batching without manually calling tick. Cover invalid-log reads-only behavior and SIGTERM cleanup. Share the production assembly function if a child process is cumbersome; avoid another copy of main's wiring in the test.

### C3 — P2 / SHOULD: signer-response tests omit the saved-position mismatch cases

Locations: `services/ledger/tests/batching/client.test.ts:129-138` and `tests/support/fake-signer.ts:11-26`; relevant implementation `src/clients/signer.ts:159-178` (`runMismatch`).

The client tests deliberately alter payload choice, and recovery tests alter signature/hash, but the fake has no fault for a missing/extra event, different seq, different ts, or different first prev_hash. A successful `sign_returns_the_positioned_run...` checks an honest fake's output; it cannot demonstrate that the client rejects a dishonest response. This matters especially for a different but quantized timestamp: a correctly signed alternative run can satisfy the ledger checker while disagreeing with the persisted sign request, undermining exact replay/recovery assumptions.

Concrete mutation: replace the seq/ts comparison at `src/clients/signer.ts:173` with `if (false)`, rebuild and run `node --test --test-reporter=tap services/ledger/dist/tests/batching/client.test.js`: **7 passed, 0 failed**, `/tmp/core-signer-position-mutation.log`. The original source was restored and rebuilt. This is a coverage gap, not a claim that current matching code is wrong. Contained fix: add response-only fault modes and assert the precise `mismatch` result for count, position and first-prev-hash independently; test one valid alternative quantized timestamp with correct signatures/hashes and assert nothing is appended and the original request remains pending. Keep the independent EV-26 checks for signature/hash defects. Do not expand the fake into an implementation of the future signer service.

### C4 — P3 / SHOULD: the rehearsal judge's verdict/exit disagreement branch is removable without failing its tests

Locations: `tools/rehearsal/test/rehearse.test.ts:143-159`; implementation `tools/rehearsal/src/rehearse.ts:121-126`.

Tests cover disagreement in the verdict and exit >=3 tool failures, but all verdict-producing judges return the expected exit. They never give `VALID` with exit 1/2, or the correct `INVALID at line N` with exit 0/2. Temporarily replacing `if (result.status !== wantExit)` with `if (false)` and rebuilding leaves the focused rehearsal judge suite green. The source was restored and rebuilt afterward.

Contained fix: inject a judge that keeps `selfJudge`'s correct stdout but deliberately changes its status. Assert the intended `... exited ..., wanted ...` error for clean and tampered cases. Add start-error and null-status negatives in the same small matrix if touching this area. No need for extra real-verifier runs.

### C5 — P3 / historical diagnostic limitation: differential fuzz harnesses report success for two nonverdicts

Locations: `docs/security/attacks/t9-reaudit-2026-10-20/fuzz.mjs:80-111` and `fuzz2.mjs:85-116`.

Both scripts normalize arbitrary stdout to `?? ...`, compare the two strings, ignore subprocess exit codes, and never set a failure exit on disagreement. They also allow zero/invalid case counts. Their READMEs present them as historical differential audit tools, not required CI tests, so this is lower priority than C1-C3; do not cite their exit status as verifier agreement.

Concrete repro using no verifier executable/source:

```sh
node docs/security/attacks/t9-reaudit-2026-10-20/fuzz.mjs /tmp/core-fuzz-probe /bin/true /tmp/nonexistent-verifier.mjs 2 1
node docs/security/attacks/t9-reaudit-2026-10-20/fuzz2.mjs /tmp/core-fuzz2-probe /bin/true /tmp/nonexistent-verifier.mjs 2 1
```

Each exits **0** and prints `cases 2, disagreements 0, go verdict mix {"??":2}`. Neither process produced a verdict. If these tools are reused, reject nonverdicts/tool failures, validate positive count, and return failure for disagreement. Retaining human-readable historical diagnostics is fine; do not promote these harnesses to gates as they stand.

## Usefulness, redundancy and layering

- Keep golden anchors, malformed-input rejection, role/owner storage guards, forced writer races, exact byte replay and HTTP contract assertions. They discriminate meaningful independent failure modes.
- Keep byte-identical fixture groups with different `head`/`chain` arguments. They are intentional distinct tests of external anchors, not duplicates. Likewise the documented 016/040 overlap is deliberate; no mass deduplication is warranted.
- Declaration tables in `phase3-batching.test.ts` and `opaque-batching.test.ts` are change detectors, not proof of the verdicts. Their committed-shape assertions and the separate ADR-0034 exact/conservative model provide substantive evidence. Avoid reporting declaration-copy counts as semantic coverage.
- `workspace.test.ts` is a small export-map consumer smoke test. Its four getter/typeof assertions are low-value individually, but jointly exercise a real package resolution seam; replacing them with one import/behavior smoke is optional, not urgent.
- `tools/rehearsal/test/build.test.ts:431-507` builds 4,000 + 12,000 chains across two tests, with expensive signing. On this machine that file took about 108 s while many other tooling files completed in seconds. It provides deterministic structural sampling and was deliberately added after seed drift; do not simply delete seeds. Consider a small always-on boundary/branch suite plus a named longer sweep if CI latency matters, preserving the structural invariants and recorded deterministic corpus. This is measured cost and a candidate optimization, not proof the sweep is excessive.
- `build.test.ts`'s opening comment says self-verification is "owed to a later slice" even though `verify.test.ts` now supplies it. Correct that stale commentary; it is not a missing test.
- The regular ledger suite and `test:verifiers` are intentionally separate; CI invokes the latter with fail-closed required database/verifier variables. Local missing-env skips are explicit. Do not merge their results into a claim that unit tests invoked the independent verifiers.
