# Pulse API test-quality audit — 2026-11-14

Audited detached `cf0707964a0c6f7c5295e18429a774f9638b5993` in `/workspace/odc-audit-api`. Report only. No application or test source changes, issue creation, commits, checkout, reset or stash. Pulse is charter-exempt; no core or verifier source was read.

The suite is substantial and usually tests observable behavior: persisted rows after failures, original idempotent responses, cross-account refusals, independent public schemas and forced database interleavings. Its green result should be retained as useful evidence. This broader review nevertheless found several concrete gaps in what individual tests prove. Three controlled mutations survived focused existing suites. These are test defects/coverage gaps, not reports that the unmodified production implementation currently has those injected defects.

## Findings

### 1. [SHOULD] P2 — Session malformed-field fixtures do not isolate the guards they claim to test

`apps/pulse/test/session.test.ts:102–123`, especially lines 114–116; implementation `apps/pulse/src/http/session.ts:94–135`.

The test correctly signs its own malformed payload, overcoming a previously documented wrong-MAC problem, but several fixture values still prevent it from exercising the intended rule. The signer uses milliseconds and the frozen clock is 2026-08-09. The literal expiry `1754744400` is interpreted as a date in January 1970. Thus the empty-voter payload `.1754740800.1754744400` is expired even if the empty-voter guard is removed. Its assertion cannot establish that guard's necessity.

The fixture commented `// fractional`, `voter-1.1.5.1754744400`, does not contain a fractional timestamp under the documented right-to-left parser: it parses as voter ID `voter-1.1`, issue time `5`, and expiry `1754744400`. Dotted voter IDs are intentionally supported (`session.test.ts:89`). This case fails because it is expired, not because it encodes fractional time. The `voter-1..1754744400` case similarly has another reason to fail; `Number("")` becomes zero, so it does not establish rejection of an absent issue time by the integer check.

Evidence level: direct fixture/parser analysis; no new session mutation run was completed. Other malformed fixtures in the same loop remain useful (NaN and unsafe integers), and ordinary expiry, tampering and revocation tests are strong. This finding does not imply that an attacker can mint an authentic malformed cookie or bypass the MAC.

Fix: construct signed payloads from `START.getTime()` and a future millisecond expiry. Add one independently invalid field per case, including empty voter ID and valid-MAC v1 generation cases. Because a dot is the field delimiter and voter IDs may contain dots, explicitly test the parser's actual accepted representation rather than calling a dotted string a fractional timestamp. Check both the decoded fixture fields and the intended refusal. Rename/remove the misleading fractional case if fractional issue times cannot be represented independently in this grammar.

### 2. [SHOULD] P2 — Contribution “500-entry cap atomically” tests only prove refusal at 500

`apps/pulse/test/contributions-http.test.ts:569–609`; guards `apps/pulse/src/contributions/store.ts:151`, `:178`, `:231`.

For participations, updates and messages, each test directly seeds 500 entries and asserts the next write returns `record_full` without changes. That is an efficient way to avoid 500 HTTP requests, but it never demonstrates that the 500th permitted entry is accepted. Nor does this particular test overlap two requests at the final available slot, despite the word “atomically” in its name.

Controlled proof: changed all three compiled guards from `>= 500` to `>= 499`, leaving source untouched. Both `contributions.test.js` and `contributions-http.test.js` passed **55/55, zero skips**, against the required real Postgres database. This mutant refuses a documented legal write and survives both relevant suites. Log: `/workspace/api-quality-contribution-caps.log`. Compiled guards were restored to `>= 500` afterwards.

Fix: seed 499 entries, arrange a caller who is below the separate 20-per-sender cap, accept one write and assert 500 persisted entries, then refuse the next. For participation/message shared-row concurrency, seed 499, force two different senders to overlap at a database barrier and assert exactly one succeeds and exactly 500 remain. Existing two-sender row-lock test (`contributions.test.ts:459`) usefully proves preservation of two writes; it does not prove the capacity boundary. For organizer-only updates the same account lock serializes writers, but a last-slot race test can still pin the complete behavior. Keep the existing rollback snapshot assertions.

### 3. [SHOULD] P2 — Uniform image fixtures cannot establish the promised centre crop or pixel orientation

`apps/pulse/test/support/images.ts:10–27`, `apps/pulse/test/image-process.test.ts:74–87`; crop implementation `apps/pulse/src/images/process.ts:163–172`.

The general picture builder creates a single solid colour. The metadata fixture is also solid. Tests inspect dimensions and metadata, so they prove important size/privacy properties, but cannot distinguish which part of an image survives a crop. The orientation test proves the width/height swap for EXIF orientation 6; a solid input cannot distinguish correct rotation from a mirror or a rotation in the opposite direction that yields the same dimensions.

Controlled proof: changed compiled thumbnail `position: "centre"` to `position: "north"`; `image-process.test.js` still passed **17/17, zero skips**. Log: `/workspace/api-quality-crop.log`. The mutation was restored byte-for-byte. This proves the centre-crop assertion is missing; the larger orientation claim is a fixture-based observation, not an independently run orientation mutant.

Fix: add an asymmetric fixture with distinguishable coloured regions and a centre marker. Decode output pixels and use tolerant region checks (WebP is lossy), asserting the centre survives while an excluded edge does not. Reuse the asymmetric fixture with selected EXIF rotations/mirrors. Keep generated solids for dimension, metadata and format tests; they are cheap and appropriate there. This is separate from #612, which owns required container-image processing/CI checks.

### 4. [SHOULD] P3 — “accepts_the_exact_limits” leaves the upper image boundaries untested

`apps/pulse/test/image-process.test.ts:153–166`; implementation `apps/pulse/src/images/process.ts:140–146`.

The refusal cases cover 8001 pixels per side, 42 megapixels and a 199-pixel short side. The exact-limit acceptance test only processes 200×200, proving the lower boundary. It does not accept an 8000-pixel side or exactly 40 megapixels.

Controlled proof: changed compiled `width > MAX_INPUT_SIDE` to `width >= MAX_INPUT_SIDE`; all **17/17** image-processing tests passed, zero skips. Log: `/workspace/api-quality-side-boundary.log`. This rejects a valid 8000×200 input under the documented contract. Restored exactly.

Fix: add an accepted 8000×200 and its transposed partner; test the exact 40-megapixel boundary with an appropriate generated fixture or an explicitly controlled metadata/decode seam. Prefer a few boundary tests over a broad matrix of expensive full decodes. Rename the current test to identify its lower-bound-only scope if the other cases remain deferred.

### 5. [SHOULD] P2 — Default mail timeout tests bound the constant without observing the default actually used

`apps/pulse/test/resend-mailer.test.ts:71–110`, `:332–358`; constructor `apps/pulse/src/identity/resend-mailer.ts:90`.

The default-options test checks the real provider URL and that `init.signal` is an `AbortSignal`; the next test bounds exported `DEFAULT_TIMEOUT_MS` between one and 30 seconds. The behavioral abort test uses an explicit `timeoutMs: 5`. These establish three separate facts but do not tie the no-override constructor path to the bounded default. Replacing `options.timeoutMs ?? DEFAULT_TIMEOUT_MS` with `options.timeoutMs ?? 600_000` would leave the constant-bound test unchanged, keep an AbortSignal in the request and preserve the explicit-5ms test. The test comment says the signal test covers the default wiring; that overstates its evidence.

Evidence level: static gap with a concrete proposed mutation, **not an executed survivor**. Automatic approval review prevented the attempted elevated probe from running because its review usage limit had been reached; the rejection explicitly said this was a review failure, not a determination that the action was unsafe. No mutation from that attempt ran.

Fix: observe the argument supplied to `AbortSignal.timeout` under default construction using a restored test-local stub, or use an injected signal/timer factory and assert the bounded default reaches it. Retain one real abort behavior test with the short explicit timeout. No need to make every suite wait ten seconds.

## Assertions, mocks, duplication and unnecessary tests

Useful patterns to preserve:

- `support/contributions-http.ts` and `support/profiles-http.ts` transcribe independent strict response schemas; unknown response fields become failures, rather than being silently dropped by a type cast. Rejection helpers compare persisted state/replay keys before and after. They use real stores and local HTTP.
- Shared conformance suites execute against both memory and Postgres. Their adapter entry files have zero direct assertions by design; they are not empty tests. Their duplication is intentional implementation parity.
- PG voting tests force a writer between aggregate reads and force lock overlap. Merely launching `Promise.all` is weaker evidence; the PG-specific barrier tests materially strengthen the conformance checks. Publication and image tests similarly observe real blocked backends.
- Rollback probes fail late (triggers during replay/audit persistence), inspect committed data and retry the same key after removing the failure. This is more useful than mocking a method to throw before any write.
- Image metadata fixtures assert the input really contains EXIF/GPS/XMP/ICC before checking absence on both encoded outputs. Public-projection tests inject extra private properties, so an overly broad spread would be detectable.
- Browser-style Origin wrapper is explicitly overridden by missing/foreign-origin cases; it does not silently make those negative cases same-origin. Vote cookie jar joins explicit session cookies rather than replacing the ballot identity.

No large deletion of tests is justified. Similar scenarios across pure/store/HTTP layers often cover different failure mechanisms. The two profile HTTP files are the clearest overlap, but one is cheap injected-memory route coverage and one verifies actual Postgres/wire behavior. Keep the shared-contract cases parameterized if maintenance grows; do not discard the real seam or memory parity.

Small excess / accuracy cleanups, below the five findings:

- `http-session.test.ts:404–421` forbids substrings `tally`, `tabulat` and `verif` under a test named “no response mentions ... how anything is counted.” ADR-0039 now explicitly allows explaining counting. This particular fixture passes today, but the lexical rule is broader than the product rule and can reject legitimate wording. Narrow it to false claims of ledger/hash-chain backing, or drop the obsolete counting-word restriction. No runtime defect is asserted.
- `session.test.ts:160` tests a generic short secret and `:164` checks31/32 exactly; the latter subsumes the former. Removing/merging the first saves little but is safe. Keep the boundary test.
- `migrate.test.ts:576` calls itself a two-query index test but asserts the complete index-name inventory. That catches removal/renaming, not column order, predicate or query-plan correctness. It is a schema snapshot with deliberate maintenance cost; rename/document that limit rather than treating it as performance proof. The static SQL checks in `migrations.test.ts` similarly enforce source spelling, while actual migrations/store tests supply behavioral evidence.
- Some legacy comments overstate evidence (“every body-taking route” in `http-body-limits` excludes later picture/profile/contribution routes, which have their own suites). Prefer accurate scope names; no need to duplicate all those cases into this older table.

## Methods, reproduction and evidence limits

Read the governing root/app guides, memory INDEX/Pulse entry, app README/API, odc-testing and odc-code-review skills, prior timing audit, issue inventory and relevant implementation. Catalogued all63 test/support/conformance files, inspected test registrations, assertion/fixture/mocking patterns and skip paths; deep semantic review and controlled proofs were concentrated on security/session parsing, shared quota/transaction boundaries, public projections, image processing and production defaults. This is broader than the previous six guard probes and does not treat their results as a substitute. It is not a claim of exhaustive mathematical correctness or that every possible input/interleaving was analyzed.

Commands included `rg --files`, `rg -n` for test/skip/assertion/route patterns, line-numbered test/source reads, and:

```sh
source /workspace/.local/bin/odc-env

node --test --test-reporter=tap \
  apps/pulse/dist/test/contributions.test.js \
  apps/pulse/dist/test/contributions-http.test.js
```

For each valid mutation, a Python runner saved target compiled bytes, applied exactly the substitution below, ran the focused command with captured stdout/stderr, and restored original bytes in `finally`. Source files were never mutated. Independent image mutations started from the same restored compiled file; they were not combined.
